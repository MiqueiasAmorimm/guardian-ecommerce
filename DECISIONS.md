# Technical Decisions — Guardian Catalog Service

This document records the key architectural and technical decisions made during the development of the catalog-service.

## UUID instead of Long as ID
Long is sequential and generated by the database. With multiple databases in microservices, product id 1 and order id 1 collide when data crosses services. UUID is generated independently, never collides.

## Flyway instead of Hibernate ddl-auto
`ddl-auto=create` can drop tables in production and lose data. Flyway versions each change as a numbered SQL file that runs once — traceable and safe.

## Rich Domain Model
Business rules stay in the entity. The `Product` entity validates name, description and price in the constructor. Rules are enforced regardless of who calls the entity.

## Environment Variables for credentials
Database credentials configured via environment variables with default values for local development. Never hardcoded in source code.

## Layered Architecture
- **domain** → business rules, no external dependencies
- **application** → use cases, orchestrates the domain
- **infrastructure** → database access, technical details
- **web** → HTTP controllers, DTOs, error handling

## Pagination on GET /products
Returns products in pages instead of all at once. Prevents performance issues with large datasets.
